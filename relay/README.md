# Gemini 중계 서버 (Cloudflare Worker)

## 서버 AI 작업 전환 (v6.90)

화면 잠금·탭 전환 뒤에도 결과를 회수하기 위한 작업 기반을 추가했다.
단계별 범위·API·배포 방법은 [JOBS_PLAN.md](JOBS_PLAN.md)에 정리했다.
2단계에서 앱의 문서·검사·Gemini/OpenAI 이미지 요청을 서버 작업에 연결했다.
로그인하고 AI 연결 설정의 서버 실행을 켜면 사용하며, 개인 키는 별도의 서버별 허용이 필요하다.
3단계에서 **도구 → AI 작업**에 새로고침·탭 재실행 후 진행 조회, 문서·검사·이미지·단편 결과 복구를 연결했다.
원본이 바뀌거나 삭제됐으면 덮어쓰지 않고 결과를 내려받을 수 있다. 문서 전체 단계의 서버 진행은 이후 단계다.
Worker는 이제 `jobs.js`·`providers.js`도 함께 가져오므로 아래의 코드 한 파일 붙여넣기 방식 대신
GitHub 연결 또는 이 폴더에서 `wrangler deploy`로 배포한다.

친구가 내 Gemini API 키로 WorldWiki.ai를 쓰게 하되, 키 자체는 보여 주지 않기 위한 중계 서버입니다.
키는 Cloudflare에만 저장되고, 친구는 **접속 암호**만 받습니다.

```
친구 브라우저 ──(접속 암호)──▶ Cloudflare Worker ──(내 API 키)──▶ Gemini API
```

- 기존 중계는 Workers 요청을 사용하며, 서버 AI 작업은 Durable Objects의 요청·실행·저장 사용량도 발생합니다. 실제 비용은 계정 플랜과 사용량에 따릅니다.
- 접속 암호가 없거나 틀린 요청, 허용하지 않은 사이트에서 온 요청은 막습니다.
- Gemini 생성과 모델 목록 조회 외의 요청은 모두 막습니다.

## 1. Worker 만들기

1. https://dash.cloudflare.com 에 가입하고 로그인합니다.
2. 왼쪽 메뉴 **Compute (Workers)** 또는 **Workers & Pages** → **Create** → **Start with Hello World!** 를 고릅니다.
3. 이름을 `worldwiki-relay` 처럼 정하고 **Deploy** 를 누릅니다.
4. **Edit code** 를 눌러 편집기에 있는 코드를 모두 지우고, 이 폴더의 [`worker.js`](worker.js) 내용을 그대로 붙여 넣은 뒤 **Deploy** 를 누릅니다.

## 2. 키와 암호 넣기

Worker 화면 → **Settings** → **Variables and Secrets** → **Add** 에서 아래 값을 넣고 저장(Deploy)합니다.

| 이름 | 종류 | 값 |
|---|---|---|
| `GEMINI_KEY` | **Secret** | Gemini API 키 |
| `PASSWORDS` | **Secret** | 접속 암호. 친구마다 다르게 주려면 쉼표로 구분 (예: `chulsoo-7f3k,younghee-q9m2`) |
| `ALLOWED_ORIGINS` | Text (선택) | 비워 두면 `https://sjh0918092-a11y.github.io` 만 허용 |

- 키와 암호는 꼭 **Secret** 으로 넣으세요. Secret은 저장 후 대시보드에서도 다시 볼 수 없습니다.
- 암호는 추측하기 어렵게 길게 만드세요.
- 특정 친구를 끊으려면 `PASSWORDS` 에서 그 암호만 지우면 바로 막힙니다.

## 3. 확인

Worker 주소(`https://worldwiki-relay.<내 계정>.workers.dev`)를 브라우저로 열면 아래처럼 보여야 합니다.

```json
{"ok":true,"service":"WorldWiki relay","keyConfigured":true,"passwordsConfigured":true}
```

`keyConfigured` 나 `passwordsConfigured` 가 `false` 면 2단계 값을 다시 확인하세요.

## 4. 앱에서 연결하고 친구 초대하기

기본 중계 서버 주소는 `index.html` 의 `DEFAULT_RELAY` 에 들어 있습니다. Worker 주소가 바뀌면 이 값을 고칩니다.
주소는 공개돼도 괜찮습니다. 접속 암호가 없으면 쓸 수 없습니다.

1. 친구에게 사이트 주소(https://sjh0918092-a11y.github.io/WW.ai/)를 보내고, 접속 암호는 **따로** 알려 줍니다.
2. 처음 들어온 사람은 자동으로 **중계 서버로 연결** 설정 화면이 열립니다. 접속 암호만 넣고 저장하면 됩니다.
3. 이미 API 키를 쓰던 사람은 기존 설정이 그대로 유지됩니다.

## 사용량 관리

- 모든 요청이 내 API 키로 나가므로, 사용량과 비용은 Google AI Studio의 사용량 화면과 Cloud 콘솔 결제 화면에서 함께 보입니다.
- Cloud 콘솔 **결제 → 예산 및 알림** 에서 예산 알림을 걸어 두세요. 알림은 한도를 넘어도 사용을 막지는 않습니다.
- 요청 수 자체를 막고 싶으면 Cloud 콘솔 **API 및 서비스 → Generative Language API → 할당량** 에서 낮출 수 있는 항목을 낮추세요.
- 친구와 같은 키를 쓰므로 분당·일일 요청 한도도 함께 나눠 씁니다.

## 문제 해결

| 증상 | 원인 |
|---|---|
| "접속 암호가 올바르지 않거나…" | `PASSWORDS` 에 그 암호가 없거나 오타 |
| "허용되지 않은 사이트입니다" | 앱을 다른 주소에서 열었음. 그 주소를 `ALLOWED_ORIGINS` 에 추가 |
| "GEMINI_KEY 또는 PASSWORDS가 설정되지 않았습니다" | 2단계 값이 비어 있거나 저장(Deploy)하지 않음 |
| `User location is not supported` | Worker가 Gemini 미지원 지역(예: 홍콩 HKG)의 데이터센터에서 실행됨. 아래 '실행 지역 고정' 참고 |

## 실행 지역 고정 (User location is not supported 해결)

Cloudflare는 Worker를 **요청한 사람과 가까운 데이터센터**에서 실행합니다. 한국 통신사에 따라 홍콩(HKG)으로 연결되기도 하는데, Gemini API는 홍콩을 지원하지 않아 이 오류가 납니다.
Worker 주소를 열었을 때 `runsIn` 의 `colo` 가 그 사람의 요청이 나가는 데이터센터입니다(친구가 직접 열어야 친구 기준 값이 보입니다).

`wrangler.toml` 의 `[placement] region = "gcp:us-east4"` 가 Worker를 미국 동부 근처에서 실행하도록 고정합니다.
이 설정은 대시보드의 코드 편집기로는 들어가지 않고, 아래 방법 중 하나로 배포해야 적용됩니다.

### 방법 A. GitHub 저장소와 연결 (권장, 명령어 없음)

1. Worker 화면 → **Settings** → **Build** → **Connect** → GitHub 에서 `WW.ai` 저장소를 고릅니다.
2. 브랜치는 `main`, **Root directory**(경로)는 `relay` 로 둡니다. 배포 명령은 기본값(`npx wrangler deploy`) 그대로 둡니다.
3. 저장하면 바로 한 번 배포되고, 이후 `relay/` 가 바뀔 때마다 자동으로 다시 배포됩니다.

### 방법 B. 내 컴퓨터에서 직접 배포

Node.js 를 설치한 뒤 저장소의 `relay` 폴더에서:

```
npx wrangler login
npx wrangler deploy
```

두 방법 모두 대시보드에 넣은 `GEMINI_KEY`, `PASSWORDS` 는 그대로 유지됩니다.
배포 후 Worker 주소를 다시 열어 `runsIn` 이 미국 쪽 코드(예: IAD, EWR)로 바뀌었는지 확인하세요.
배치는 Cloudflare가 지키려고 노력하는 "힌트"라서 드물게 다른 곳에서 실행될 수도 있습니다.

## 계정과 세계관 저장 (Cloudflare D1)

앱의 'Gemini 설정 → 계정'에서 가입하고 로그인하면 세계관이 서버에 저장되어, 다른 기기에서 같은 아이디로 로그인해도 보입니다.

- 저장소는 Cloudflare D1(`worldwiki-db`)입니다. `wrangler.toml`의 `[[d1_databases]]`에 Database ID가 들어 있고, 테이블은 Worker가 첫 요청 때 스스로 만듭니다.
- 가입할 때 초대 코드로 `PASSWORDS` 중 하나(접속 암호)를 받습니다. 아무나 가입해 저장 공간을 쓰지 못하게 하기 위해서입니다.
- 비밀번호는 PBKDF2 해시로만 저장합니다. 관리자도 비밀번호는 볼 수 없지만, 세계관 내용은 대시보드의 D1 → `worlds`, `pages` 테이블에서 볼 수 있습니다.
- 같은 문서를 두 기기에서 고치면 수정 시각이 더 최근인 쪽이 남습니다.
- 무료 한도(하루 쓰기 10만 번, 저장 5GB) 안에서 씁니다.

### 관리

D1 화면의 **Console**에서 SQL로 관리합니다.

| 하고 싶은 것 | SQL |
|---|---|
| 가입한 사람 보기 | `SELECT id, created FROM users;` |
| 비밀번호를 잊은 사람 지우기(세계관은 남음, 같은 아이디로 다시 가입하면 이어서 보임) | `DELETE FROM users WHERE id = '아이디'; DELETE FROM sessions WHERE uid = '아이디';` |
| 어떤 사람의 저장 데이터까지 모두 지우기 | `DELETE FROM pages WHERE uid = '아이디'; DELETE FROM worlds WHERE uid = '아이디';` |

Worker 주소를 열었을 때 `storageConfigured`가 `true`면 저장소가 연결된 것입니다.

## 문서 이미지 생성

앱의 **프로필 이미지 / 문서 이미지 → AI로 생성**에서 한 장을 생성하고 미리 본 뒤 적용한다.
세계관 설정 노트의 **세계관 공통 이미지 지침**은 모든 문서의 새 이미지 생성에 전달된다.
지침을 저장해도 기존 이미지는 바뀌지 않는다. 이미지 일괄 교체 기능은 없다.

기본 이미지 모델은 `gpt-image-2.5-flare`다. Gemini 이미지 모델도 `gemini-nano-banana-2.1`, `gemini-3.1-flash-lite-image`, `gemini-3-pro-image` 중에서 선택할 수 있다.
AI 연결 설정의 기본 이미지 모델을 바꿀 수 있다. 이미지 생성은 유료 API 사용량에 포함된다.

Gemini 이미지 모델은 공식 `generateContent` 이미지 생성 경로를 사용하므로 기존 Worker를
다시 게시하거나 별도 이미지 API 키를 추가할 필요가 없다.
네트워크 오류나 생성 실패를 자동 재시도하지 않아 중복 과금을 피한다.

기존 이미지를 참조하도록 선택하면 축소 저장된 이미지를 Gemini에 보낸다.
생성 결과는 적용 전까지 미리보기로만 유지되며, 적용 후에는 기존 문서 저장·백업·동기화에 포함된다.

업로드·생성 이미지는 원본 비율을 유지하며 긴 변 최대 2048px로 저장한다. 작은 원본을 늘려 저장하지는 않는다.
문서 이미지와 생성 미리보기를 누르면 확대창에서 화면 맞춤·100% 크기로 볼 수 있다.
이전 버전이 이미 축소 저장한 이미지의 해상도를 높이려면 원래 파일을 다시 업로드해야 한다.

### OpenAI 이미지 모델

**AI 연결 설정 → OpenAI API 키 (이미지 생성용)**에 키를 넣고 **저장**한다.
이미지 생성창에서 `OpenAI · GPT Image 2.5 Flare` 또는 `OpenAI · GPT Image 2.5 Sunburst`를 선택한다.
설정의 **기본 이미지 모델**에도 지정할 수 있다. Gemini의 문서 작성·검사 모델과 연결은 그대로 유지된다.

직접 연결에서는 브라우저에서 `https://api.openai.com/v1/images/generations`로 요청한다.
기존 이미지 참고를 선택하면 `images/edits`에 multipart로 이미지를 함께 보낸다.
Gemini 키·중계 암호는 OpenAI로 보내지 않으며 OpenAI 키도 Gemini로 보내지 않는다.
OpenAI 키의 연결 설정은 이 브라우저 localStorage에 저장되며 백업·세계관 동기화에 포함되지 않는다.
v6.89의 서버 실행과 개인 키 허용을 켜면, 로그인한 계정의 서버 작업이 OpenAI 요청을 대신 실행하고 키를 대기·실행 동안만 임시 보관한다.
직접 연결만 사용하면 Worker 재배포가 필요 없고, 서버 AI 작업을 사용하려면 v6.89 Worker 배포가 필요하다.

ChatGPT 구독과 별도로 OpenAI API 사용료가 발생한다. 조직 인증이나 모델 접근 권한이 필요할 수 있다.
품질은 기본 `high`, 선택지는 `low` / `medium` / `high` / `auto`다. 출력은 PNG 한 장이며,
비율별 생성 크기는 1:1 1024×1024, 3:4 1152×1536, 4:3 1536×1152, 9:16 864×1536, 16:9 1536×864다.
생성은 최대 5분 기다리고 자동 재시도하지 않는다. 중단해도 이미 시작한 서버 처리의 과금 취소가 보장되지는 않는다.
공통 이미지 지침·문서·추가 요청·미리보기 적용 절차는 Gemini와 같다. ChatGPT 채팅과 같은 결과를 보장하지 않는다.

공식 API 기준: https://developers.openai.com/api/docs/guides/image-generation

### 기본 이미지 모델과 문서 응답 복구 (v6.19)

새 연결의 이미지 기본값은 OpenAI Flare다. 이전 기본값인 Nano Banana 2.1만 사용하던 연결은
한 번 OpenAI 기본값으로 이전한다. Pro·Lite·Sunburst 등 따로 고른 모델은 보존한다.
이후 사용자가 다시 Nano Banana 2.1로 바꾸면 다음 접속에서도 그 선택을 유지한다.
OpenAI 키의 저장 위치와 연결 방식은 이번 변경에서 바꾸지 않는다.

문서 작성(`page`)·설정 대조(`check`)·문서 내부 읽기 검사(`read`)는 출력이나 사고 토큰의
진행을 감지한다. 첫 진행은 최대 3분 기다리며, 진행이 시작된 뒤 80초간 멎으면 해당 요청을 복구한다.
SSE 연결 유지 주석·빈 이벤트는 진행으로 세지 않는다. 진행 중인 요청을 총 80초가 지났다는 이유로 다시 보내지 않는다.
부분 출력은 기존 이어 받기 로직을 사용하고, 재시도는 최대 2회, 복구 시간을 포함한 호출당 최대 대기는 10분이다.
사용자 중단은 재시도하지 않는다. 이미지 생성에는 이 정책을 적용하지 않는다.
검사 자료의 선정 범위·프롬프트와 자동 검사 시점은 바꾸지 않았다.

## 문서 기반 단편 (v6.20)

작성된 문서의 **단편 쓰기**를 누르고 내용·분위기·문체·시점을 자유롭게 입력한다.
분량은 약 2,000~3,500자 / 5,000~8,000자 / 10,000~15,000자 중에서 고르며, 실제 분량은 모델 응답에 따라 달라질 수 있다.
글쓰기는 AI 연결 설정의 기존 Gemini 기본 문서 모델을 사용한다. OpenAI 키는 이미지 생성용으로 유지된다.

기준 문서 전체, 세계관 원안·핵심 규칙·사용자 확정 설정·연표, 해당 대상의 확정 사실·언급·관계,
관련 항목과 스토리 모드의 장 시점을 참고해 산문을 생성한다. 문서 요약보다 장면·행동·대화 중심으로 쓰도록 지시한다.
단편 요청에도 v6.19의 실제 진행 감지·정체 복구를 적용한다. 기존 설정 검사의 자료 범위는 변경하지 않는다.

생성 결과는 먼저 미리보기로 표시하고 **이 단편 보관**으로 문서당 최대 20편 저장한다.
원본이 생성 중 바뀌었으면 보관을 거절하고 결과를 유지한다. 단편은 문서의 `shortStories`에 별도로 저장되며
기존 문서 저장·서버 동기화·JSON 백업에 포함된다. 저장 실패 시 미리보기는 사라지지 않는다.
새 대사·묘사는 확정 사실·언급·연표·관계로 추출하지 않고, 문서 본문이나 설정 검사에 자동 반영하지 않는다.

보관한 단편은 API 연결 없이도 읽을 수 있다. 직접 편집·AI 다시 쓰기·장 반영·교정 뒤에도 유지하고,
문서를 합칠 때에는 두 문서의 보관 단편을 함께 남긴다. 단편 삭제는 한 번 더 확인하며,
문서 자체를 삭제하면 그 문서에 보관한 단편도 삭제된다.

### 단편 삽화 (v6.21)

보관한 단편을 펼치고 **삽화 한 장 만들기**를 누른다. 모델·화풍·비율·장면 추가 요청을 고를 수 있다.
단편 전체, 문서의 설정, 세계관 공통 이미지 지침을 이미지 모델에 전달한다.
문서 프로필이 있으면 외모 일관성을 위한 참고로 자동 첨부한다. 이전 삽화는 참고로 보내지 않는다.
얼굴·머리카락·피부색 등 정체성만 참고하고, 프로필의 구도·포즈·카메라·배경·조명·색감·화풍이나
배경만 바꾼 변형을 복제하지 않도록 명시한다. 의상·장비는 문서와 단편의 장면에서 결정한다.
이는 모델에 전달하는 지시이며, 결과가 지침을 얼마나 지켰는지는 적용 전 미리보기에서 확인해야 한다.

프로필이 있으면 OpenAI `images/edits`, 없으면 `images/generations`를 사용한다.
Gemini는 기존 이미지 생성 API에 프로필 inlineData를 함께 보낸다.
기존 API 설정·과금 방식을 사용하고 이미지 생성 실패를 자동 재시도하지 않는다.

삽화는 미리보기 후 적용하며 단편의 `illustration` 필드에 한 장만 저장한다. 문서 프로필은 바꾸지 않는다.
확대·재생성·확인 삭제를 지원한다. 생성 중 단편·문서·프로필·기존 삽화가 바뀌면 적용을 거절한다.
단편과 함께 백업·동기화·편집·다시 쓰기·문서 합치기에 포함된다. 별도 Worker 배포는 필요 없다.

### 추가 참고 이미지 제거 (v6.24)

구도·조명·화풍용 추가 이미지 업로드 기능은 제거했다.
문서 프로필의 외모 전용 자동 참조, 단편 삽화 생성·보관과 기존 이미지는 유지한다.

## 세계관별 선택 내보내기 (v6.23)

세계관의 **설정 노트 맨 아래 → 이 세계관 내보내기**에서 현재 세계관 하나만 JSON으로 받는다.
설정과 문서는 항상 포함하며, **이미지 포함**과 **단편 포함**은 각각 선택한다. 기본값은 둘 다 포함이다.

- 이미지 끄기: 문서의 `portrait`와 단편의 `illustration`을 파일에서 제외한다. 단편 본문과 요청·제목·날짜는 남는다.
- 단편 끄기: `shortStories` 전체를 제외하므로 해당 단편의 삽화도 포함되지 않는다.
- 둘 다 끄기: 세계관 설정과 위키 문서만 내보낸다. 공통 이미지 지침은 텍스트 설정이므로 유지한다.

제외는 다운로드할 사본에만 적용하고 브라우저·서버의 원본을 삭제하지 않는다.
선택 상태는 현재 세션에서 세계관별로 유지한다. 설정 노트의 미저장 입력은 자동 저장하지 않으므로,
설정을 고쳤다면 먼저 **설정 저장**을 누른다.
기존 백업과 같은 `app: worldwiki, version: 1, worlds, pages` 형식이며 **AI 연결 설정 → 가져오기**에서 복원한다.
API 키는 포함하지 않는다. 기존 **AI 연결 설정 → 백업 → 내보내기**는 계속 모든 세계관과 미디어를 포함한다.

## 문단별 편집과 AI 수정 (v6.25)

문서의 각 문단 제목 오른쪽 **[편집]**을 누르면 해당 문단만 편집한다.
상위 문단은 이어지는 하위 문단까지, 하위 문단은 그 문단 하나만 대상으로 한다.
제목과 위키 문법 본문을 직접 수정하거나 **AI 수정·다시 쓰기 방향**을 적어 초안을 받을 수 있다.
AI는 기존 Gemini 기본 문서 모델로 문서 전체와 확정 설정을 참고하며 선택한 범위만 응답한다.
수정 방향을 비우면 확정 내용과 결말을 유지하는 기본 다시 쓰기를 한다.
AI 결과는 편집 칸에서 확인·추가 수정하거나 **AI 수정 전으로** 되돌린 뒤 저장한다.

선택한 문단의 제목 수준과 이야기 장 소속을 유지한다. 다른 상위 문단을 추가하는 응답은 거절한다.
선택하지 않은 본문은 공백과 문단 메타데이터까지 유지하고 인포박스·분류·틀·이미지·단편도 보존한다.
저장은 기존 직접 편집과 같은 설정 대조·충돌 확인을 거치며 추가 자동 설정 검사를 예약하지 않는다.
API 연결이 없으면 직접 편집을 바로 저장할 수 있고, 대조 실패 시 기존처럼 **대조 없이 저장**도 가능하다.

AI 중단·잘못된 응답·저장 실패 시 초안을 보존한다. 다른 기기나 장 반영으로 원본 문서가 바뀌면
덮어쓰지 않고 다시 열도록 안내한다. 프로필·단편만 바뀐 경우에는 최신 미디어를 보존해 저장한다.

## 모바일 화면 꺼짐·탭 전환 후 복귀 (v6.26)

숨겨진 탭의 정지 시간을 API의 무응답 시간으로 계산하지 않는다.
텍스트 스트림의 무응답·최대 대기와 문서 이미지·삽화의 생성 제한은 화면이 보이는 시간 기준으로 계산한다.
화면으로 복귀하면 최소 10초 동안 버퍼의 응답을 읽을 여유를 주며, 브라우저가 타이머 실행 자체를 늦춘 경우에도 즉시 끊지 않는다.
새 텍스트 요청과 연결 복구 재시도는 화면으로 돌아온 뒤에만 보낸다.

연결이 실제로 끊기면 기존의 제한된 재시도·부분 JSON 이어 받기를 사용한다.
완료 신호 없이 스트림이 끝난 경우도 미완료 JSON이면 복구 대상으로 처리한다.
사용자 중단은 재시도하지 않고, 이미지 생성은 중복 과금을 피하려고 자동 재시도하지 않는다.
설정 검사의 자료 범위와 자동 실행 시점은 변경하지 않는다.

이 변경이 모바일 OS의 백그라운드 네트워크·실행 중단을 해제하지는 않는다.
브라우저가 탭을 메모리에서 없애거나 페이지를 새로 로드하면 실행 중 작업의 계속 수행은 보장할 수 없다.
페이지 생존과 무관하게 완료시키려면 별도의 서버 작업 큐·결과 저장과 복귀 조회가 필요하다.
브라우저 가시성·가상 시계로 복귀를 검증하며 실제 iPhone의 절전·메모리 종료는 별개 조건이다.

## 랜덤 서핑과 설명형 새 문서 (v6.27)

검색창 옆 **랜덤 서핑** 아이콘을 한 번 누르면 세계관에 어울리는 새 대상을 선정한 뒤 문서를 작성한다.
**길게 누르기(0.5초)** 또는 **더블클릭·두 번 탭**은 설명 입력창만 연다.
입력창에서는 이름뿐 아니라 대상의 종류·역할·특징을 적을 수 있으며, 이름을 지정하지 않으면 모델이 정한다.
예: “미국의 마라톤 선수. 이름은 제임스 그레이.” 기존 검색은 기존 방식대로 제목을 입력해 찾거나 작성한다.

선정 단계는 원안·규칙·사용자 확정 설정·작가 지침·대표 문서·현재 장 시점과 기존 항목 전체를 본다.
단순히 유형을 다양하게 뽑기보다 세계관의 중심 특징에서 파생되는 역할과 생활상을 우선하고,
`connection`으로 세계관과의 직접적인 연결을 설명하게 한다. 설명을 자연스럽게 수용할 수 없으면 거절 이유를 반환할 수 있다.
모델 기반 선정이므로 실제 소재와 문서 품질은 결과를 확인해야 한다.

기존 작성 문서와 빨간 링크·미작성 항목 모두 제외한다. 제목·별칭 키·인포박스의 본명/코드명 등을
로컬에서 확인하고, 의미가 같은 대상은 선정 모델도 기존 항목 목록의 정의와 대조한다.
기존 대상이면 설명형 입력은 안내만 하고 생성하지 않는다. 랜덤은 기본 모델로 중복 후보를 총 3번까지 고른다. 설명형 입력은 사용자 요청을 다른 대상으로 바꾸지 않고 중복이면 중단한다.
작성 단계가 기존 대상으로의 넘겨주기나 기존 인물의 본명을 반환해도 합치거나 덮어쓰지 않고 새 후보를 폐기한다.
선정·작성 중 저장된 기존 항목 목록이 바뀌었으면 중단하고 세계관을 다시 열도록 안내한다.

선정(개념 중복 판단 포함)·본문 작성은 AI 연결 설정의 **기본 모델**과 해당 생각 깊이를 사용한다. 작성·최초 자동 검사·저장·스토리 탐험 흐름은 기존 방식을 재사용한다.
선정/본문 작성 모두 중단할 수 있으며 실패·중단한 후보는 미작성 항목으로 남기지 않는다.
한 번 누르기는 0.35초 기다려 더블클릭과 구분하므로 입력창과 유료 생성이 동시에 실행되지 않는다.
이미 다른 편집·생성 작업이 진행 중이면 먼저 마치거나 중단한다. 모바일 숨김·복귀 처리는 기존 정책을 따른다.

### 선정 요청 안에서 한 번만 개념 중복 판단 (v6.31)

이름·콘셉트를 정하는 기본 모델 요청에 중복 판단을 합쳤다. v6.30의 별도 후보 비교와 본문 완성 후 비교 요청은 제거했다.
선정 요청에 기존 항목 전체의 제목·유형·요약·명시된 다른 이름·확정 사실·다른 문서의 언급을 한 번 제공한다. 미작성 빨간 링크도 동일하게 제외한다.
모델은 최종 후보와 함께 `novelty` 판정·근거·가장 유사한 기존 항목 최대 3개의 정확한 key 및 차이를 반환한다.
이름 변경·동의어·역할과 기능의 중복·기존 개념의 범위 쪼개기/확대를 피하되, 실제로 별개인 인물·사건·기능은 허용한다.
모호하거나 비교 근거가 없으면 새 검사를 요청하지 않고 중단한다. 명확히 겹치는 랜덤 후보는 이유를 다음 선정에 전달하며 최대 3번까지만 고른다.
설명형 입력은 사용자 요청을 바꾸지 않고 중복이면 중단한다. 선정·작성 중단과 목록/설정 변경 보호는 유지한다.
선정에서 확인한 차이는 본문 작성 지침에 전달한다. 제목·별칭·본명 충돌과 생성 응답의 넘겨주기는 기존 로컬 검사로 계속 막는다.
정상 생성은 선정(중복 판단 포함) 1회와 본문 작성 1회이며 별도 의미 비교 API 요청은 없다. 기존 최초 설정 검사 등은 별도다.
의미 판정은 선정 모델에 의존하므로 완전 차단을 보장하지 않으며, 본문 완성 후 의미가 겹치는지는 별도 재심사하지 않는다.

### 화면 주소와 방문 기록 (v6.29)

화면 이동을 `#view=article&world=세계관ID&key=문서키` 같은 주소와 브라우저 방문 기록에 남긴다.
GitHub Pages 하위 경로를 유지하므로 서버 라우팅 설정 없이 새로고침 후 같은 문서를 복원한다.
뒤로·앞으로가기는 세계관·문서·설정 화면과 스크롤 위치를 복원한다. 화면 재렌더링은 기록을 추가하지 않는다.
주소는 해당 브라우저/계정에 저장된 세계관을 가리키며 세계관 데이터를 공유하거나 공개하지 않는다.
편집 초안·교정안·다음 장 입력 같은 임시 작업은 새로고침 시 저장된 문서로 돌아간다. 편집 중 브라우저 방문 기록 이동은 초안 보호를 위해 막는다.
복원은 미작성 문서를 자동 생성하거나 설정 검사를 실행하지 않는다. 사라진 문서는 세계관 대문, 사라진 세계관은 메인으로 돌아간다.

### 숫자의 대상·속성 구분 (v6.32)

로컬 숫자 대조에서 도입·개발·설립/창설·제정·시행/발효·건국·창간·개교·성립을 하나의 기원 연도로 취급하던 동작을 제거했다.
인포박스의 명확한 속성만 기준값으로 삼고, 같은 사건의 연도를 명시적 주어 또는 ‘대상의 사건 연도’ 형태로 쓴 문장만 대조한다.
이름이 목적어/수식어로 언급됐거나, 다른 주체·소유자·복합절·부정·비교로 귀속이 모호한 경우는 기계적으로 맞추지 않는다.
1960년대·경/무렵/전후·기간 범위도 정확한 연도와 동일한 값으로 취급하지 않는다. 명확한 출생/사망 연도·사망 나이·기준 문서 우선 규칙은 유지한다.
기존 설정 대조/문서 읽기 프롬프트에도 주체·속성·사건·단위·시점·범위를 확인하도록 지침을 추가했다. 참고 자료 선별 범위·검사 시점·API 호출 수는 바꾸지 않았다.
한국어의 복잡한 문장을 완전히 분석하는 방식은 아니므로 모호한 사례는 누락될 수 있다. 저장된 예전 검사 메모는 사용자가 다시 검사하면 갱신하며, 업데이트가 자동 재검사나 기존 서술의 일괄 수정을 시작하지 않는다.

### 장르에 맞는 스토리 누적 기록 (v6.34)

사건 확대·매 장 새 항목·탐험 최소 반영·상처 자극·반전의 개수를 강제하지 않는다. 뼈대는 잠정 계획이며 확정 사건과 선택에 따라 현재/미래 단계를 수정할 수 있다. 별도 AI 검사는 추가하지 않고 기존 장 계획 응답 안에서 기록을 함께 갱신한다.

`world.story.continuity` 버전 2는 `focus`, `threads`, `choices`를 보관한다. 각 기록은 질문을 강제하는 `question` 대신 내용형 `subject`와 `kind`를 사용한다. 유형은 목표(goal), 관계(relationship), 약속(promise), 갈등(conflict), 행동의 여파(consequence), 진행 중인 일(ongoing), 실제 의문·단서(mystery)다. 일반적인 기본 기록은 인물들의 생활과 선택으로 시작하며 모든 장르를 중심 수수께끼로 만들지 않는다.

상태는 이어짐(active), 변화(changed), 성취·이행(fulfilled), 좌절(failed), 포기(abandoned), 계속됨(continuing)이다. 이번 장에 변화가 없으면 `unchanged`로 이유를 남기고 이전 상태를 유지한다. 변화를 주장할 때는 실제 이번 장 본문에서 12자 이상의 인용을 요구하며, 성취·좌절·포기는 `outcome`에 구체적인 결과가 필요하다. 관계나 일상을 변화 없이 유지/계속할 때는 인위적인 장면·해결 답·불이익을 요구하지 않는다. 마지막 장에서도 전부 정리하도록 강제하지 않는다. 장르와 원안에서 실제 약속한 중심 내용은 그에 맞게 다뤄야 한다는 지침을 준다.

기존 진행 중인 기록은 다음 장에 누락할 수 없으며 출처·원문·이력·과거 선택의 영향을 유지한다. 새로운 기록도 존재하는 출처와 인용을 확인한다. 중요한 관계 변화와 약속은 질문형이 아닌 내용형으로 기록할 수 있고, 필요 없는 설정을 모두 복선으로 취급하지 않는다. 출처 발췌는 특정 미스터리 단어 검색 대신 문서 앞·중간·뒤를 분산해서 대표하며, 이미 기록된 원문은 계속 전달한다. 모든 문서의 모든 내용을 보낸다는 의미는 아니다.

v6.33의 버전 1은 읽기 전용으로 버전 2에 대응시킨다. id·출처·원문·이력·선택은 그대로 두고, 예전 질문/답/상태도 `legacy`에 보관한다. 자동 생성됐던 기본 질문만 일반적인 생활·선택 표현으로 바꾸고, 나머지는 의미를 추정해 전부 mystery로 분류하지 않고 legacy(이전 기록)로 둔다. 장 계획에서 실제 내용에 맞게 kind/subject를 정리할 수 있다. 보관용 legacy 사본은 프롬프트에 중복 전송하지 않는다. 다음 장이 성공할 때 새 기록을 저장하며, 화면을 보거나 프롬프트를 만들기만 해서는 원본을 변경하지 않는다. 구버전 모델 응답의 상태·question/answer도 호환 입력으로 처리한다.

예전 세계관에 기록 자체가 없으면 다음 장 요청에서 중요한 목표·관계·약속·갈등·여파를 출처와 함께 복원한다. 실제 의문일 때만 mystery다. 완결된 이야기는 자동으로 다시 쓰지 않는다. 기존 장 전환 중단/실패 롤백·본문·프로필·단편 보존과 백업/동기화 흐름은 유지한다.

비밀은 예정된 장 번호만으로 공개하지 않고 실제 본문 인용으로 확인한다. 미공개 답의 집필 계획은 출처 근거를 남겨 수정할 수 있으나 이미 공개된 진실을 바꾸지는 않는다. 다음 장/완결 화면에서 기록 유형·상태와 선택 결과를 확인할 수 있다.

누적 기록과 문서 발췌로 입력·출력 분량은 늘어난다. 검사 범위 선별·자동 설정 검사 시점은 바꾸지 않았다. 코드는 기록 누락·잘못된 id/유형·없는 인용·비어 있는 결과를 검증하며, 문학적 충분함·장르 적합성·선택의 실제 의미와 과거 자료의 복원 품질까지 기계적으로 증명하지는 못한다.

### 단편 분량 확대 (v6.35)

짧게 2,000~3,500자, 보통 5,000~8,000자, 길게 10,000~15,000자로 모든 선택지를 확대했다. 본문·공백 포함 목표이며 제목은 제외한다. 하한을 기준으로 충분한 행동/대화/장면을 쓰고 긴 분량은 연결된 여러 장면으로 전개할 수 있게 지시한다. 실제 분량은 모델에 따라 달라지며, 짧다는 이유로 추가 AI 호출이나 자동 분량 채우기를 하지 않는다. 기존 60,000자 응답 검증 상한과 저장/복원 기능은 그대로 유지하며 미리보기·저장에서 본문을 잘라내지 않는다.

### 장 본문을 버리지 않는 진행 기록 복구 (v6.36)

비밀 목록에 실제 id를 주지 않은 채 `revealNow.id`를 요구하던 프롬프트를 수정했다. 공개/계획 수정은 없을 때 빈 배열을 예시로 주고, 상태/유형/중요도 예시에 슬래시 나열을 넣지 않는다. 허용 값은 규칙에 별도로 명시한다.

한글 상태와 일부 구버전 상태, state/description/change/detail/summary/result 같은 필드 별칭을 정규화한다. 설명이 누락돼도 검증 가능한 결과/인용으로 채울 수 있으면 받아들인다. 인용은 위키 표시·유니코드·공백·문장부호 차이를 정리해 비교하며, 의미를 추측하는 유사도 판정은 하지 않는다.

기본 장 형식이 유효하면 보조 기록 오류만으로 장 전체를 롤백하지 않는다. 확인 가능한 갱신은 적용하고, 없는 id/출처/인용이나 빈 완료 결과는 적용하지 않은 채 이전 기록을 유지한다. 사용자 선택 자체는 결과 메타데이터가 빠져도 보관하고 pending으로 표시한다. 장별 continuity.warnings와 유지 이력을 저장하며 장 안내 및 진행 기록의 확인 메모에서 볼 수 있다. 후속 장 요청에도 최근 보류 메모를 제공한다.

공개 인용이 틀린 경우 임의로 공개 확정하지 않고 pendingDisclosure로 보류한다. 공개된 것도, 전혀 공개되지 않은 것도 자동 단정하지 않도록 기존 본문 우선 지침을 준다. 이미 공개한 비밀의 중복 표시에는 새 인용을 강제하지 않는다. 구버전 진실 문자열, secretId/quote 별칭과 실제 원문을 확인할 수 있는 이전 출처도 지원한다. 공개된 진실의 잘못된 계획 수정은 이전 진실을 유지하고 확인 메모를 남긴다.

추가 AI 요청이나 자동 본문 재생성은 없다. 본문/필수 장 형식이 잘못됐거나 사용자가 중단한 경우의 기존 롤백은 유지한다. 이 복구는 의미상 모순을 해결한 것으로 가장하지 않으며, 확인하지 못한 부가 기록은 남아 있을 수 있다. 새 장 본문과 기존 자료를 통해 후속 진행에서 정리할 수 있도록 보존한다.
